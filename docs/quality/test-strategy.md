# Test Strategy

## 목적

FITWISE의 기능, 데이터, 개인정보 보호와 복구 가능성을 반복해서 검증한다. 테스트를 많이 실행했다는 사실이 아니라 어떤 버전·환경·데이터에서 무엇을 확인했고 어떤 제한이 남았는지를 증명한다.

## 테스트 계층

| 계층 | 대상 | 필수 시점 |
|---|---|---|
| 정적 검사 | TypeScript·Python 형식, 타입, 비밀값 | 모든 PR |
| 단위 | 입력 검증, 필터, 점수, 상태 전이 | 로직 변경 PR |
| API 계약 | 정상·빈 결과·400·422·500 응답 | API 계약 변경 PR |
| 통합 | repository, PostgreSQL, RLS, Storage | 데이터 계층 도입 후 |
| E2E | 검색→추천→근거→피드백 | 핵심 흐름 완성 후 |
| 실기기 | Android/iOS, 접근성, 네트워크 변화 | UI 변경 PR·릴리스 후보 |
| 데이터 품질 | 중복·누락·범위·최신성·권리 | 수집 실행마다 |
| 보안 | 권한 거부, 마스킹, 삭제, 비밀값 | 인증 변경·릴리스 후보 |
| 복구 | backup restore, migration rollback | DB 변경·월간·릴리스 후보 |
| AX 평가 | 필터 위반·근거 일치·안정성·비용 | 규칙·모델·프롬프트 변경 |

## 필수 시나리오

### 모바일

- 입력이 비어 있거나 예산 범위가 잘못된 경우
- 요청 중 중복 제출
- 추천 결과 없음
- 네트워크 오류 후 다시 시도
- 서버가 검증 오류 또는 안전한 일반 오류를 반환
- 글자 확대, 스크린 리더 라벨과 터치 영역
- Android와 iOS에서 키보드·스크롤·안전 영역

### API와 추천

- 같은 유효 입력은 같은 규칙 버전에서 안정적인 점수를 반환
- 예산·제외 속성·재고·사이즈 하드 필터 위반이 없음
- 상품 데이터가 부족하면 근거와 신뢰도를 제한
- AI 설명이 실패해도 구조화된 점수와 주의점을 반환
- 입력·토큰·내부 오류가 응답과 로그에 노출되지 않음

### 데이터와 SQL

- PK·FK·UNIQUE·CHECK·NOT NULL 위반 차단
- 동일 idempotency key 재처리 시 중복 행이 생기지 않음
- transaction 중간 실패 시 전체 변경 rollback
- migration 전후 row count와 핵심 checksum 비교
- 격리 데이터가 검색 색인과 추천 후보에 포함되지 않음
- 최신 백업을 별도 환경에 복구하고 핵심 조회 실행

### 개인정보와 보안

- 다른 사용자의 프로필·옷장·추천 이력 접근 거부
- 익명·인증 사용자·서버·관리자별 허용·거부 행렬
- 로그, Sentry, 화면 캡처와 CI 출력에서 민감 필드 마스킹
- 계정 삭제 후 DB, Storage, cache와 index의 처리 결과 확인
- 앱 번들·Git history·환경 파일에 비밀값이 없는지 검사

## 환경과 테스트 데이터

| 환경 | 데이터 | 외부 전송 |
|---|---|---|
| local | 합성 데이터 | 금지 |
| CI | 고정 fixture | 금지 |
| staging | 합성 또는 명시적으로 허가된 샘플 | 승인된 서비스만 |
| production | 실제 사용자 데이터 | 정책·동의·최소 권한 적용 |

CI와 개발 캡처에 실제 신체정보, 검색 원문, 사진, 연락처, 토큰과 운영 데이터를 사용하지 않는다. 고정 fixture는 버전 관리하고 추천 로직 변경 전후를 같은 데이터로 비교한다.

## 실행 기록

각 실행은 [test-log.md](test-log.md)에 다음 정보를 기록한다.

- 실행 일시와 실행자
- 환경, OS·기기·브라우저와 앱/API 버전
- Git commit 또는 PR
- 테스트 명령 또는 수동 시나리오
- 기대 결과와 실제 결과
- 성공·실패·차단 상태와 테스트 개수
- 개인정보를 제거한 증빙
- 관련 Issue·수정 PR·재검증 날짜
- 경고, 미실행 검사와 이유

실패한 실행은 삭제하지 않는다. 수정 후 새 실행을 추가하고 이전 기록과 연결한다.

## PR 검증 선택

| 변경 | 최소 검사 |
|---|---|
| 문서만 | 링크·경로, Markdown 구조, 비밀값·개인정보 확인 |
| 모바일 | lint, typecheck, unit, 빌드 또는 Expo 검증, 대상 실기기 |
| API | unit·contract·integration, OpenAPI 변경 검토 |
| SQL migration | 제약 조건, 순방향 적용, rollback/roll-forward, restore |
| 추천 | 고정 평가셋, 변경 전후 점수·근거·불확실성 |
| 인증·개인정보 | RLS 허용·거부, 삭제, 로그 마스킹, 보안 리뷰 |

## 통과 기준

- 필수 검사가 모두 성공하고 CI가 녹색이다.
- 필터 위반, 권한 우회, 데이터 손상과 비밀값 노출이 없다.
- 실패 시나리오가 안전한 사용자 상태와 복구 경로를 제공한다.
- 테스트 증빙과 알려진 제한이 PR과 실행 기록에 연결돼 있다.
- 실기기·외부 계정처럼 자동화하지 못한 검사를 사람이 확인했다.

측정하지 않은 검사를 통과로 기록하지 않으며, 실행할 수 없으면 이유와 다음 담당자를 남긴다.
