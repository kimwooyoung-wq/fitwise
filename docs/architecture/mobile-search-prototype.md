# Mobile Search Prototype

## 목적

설문 결과로 기능 우선순위를 확정하기 전에, 사용자가 `상황과 예산 입력 → 추천 이유·주의점 확인` 과정을 이해하고 완료할 수 있는지 검증한다. 이 구현은 최종 추천 정확도를 증명하지 않으며 합성 상품만 사용한다.

## 구조

```text
apps/mobile
├── src/app                 # Expo Router 화면
├── src/api                 # FastAPI 클라이언트
├── src/components          # 추천 결과 UI
└── src/domain              # API 타입과 입력 검증

services/api
├── app/main.py             # FastAPI와 OpenAPI 진입점
├── app/models.py           # 요청·응답 계약
├── app/recommender.py      # 결정적 추천 규칙
├── app/catalog.py          # 합성 상품 카탈로그
└── tests                   # API·계약·필터 테스트
```

## 검증 순서

1. Pydantic 모델로 요청·응답 계약을 먼저 정의한다.
2. `/openapi.json` 계약 테스트를 통과시킨다.
3. Swagger UI `/docs`에서 정상·검증 오류·빈 결과 요청을 실행한다.
4. 모바일 앱을 연결하고 로딩·성공·빈 결과·오류·재시도를 확인한다.
5. 실제 사용자에게 검색 문구 작성과 세 추천 전략 비교 과제를 수행하게 한다.

Swagger는 사용자 가치 검증을 대신하지 않는다. API 계약과 예외 상태를 개발 단계에서 검증한 뒤, 프로토타입 사용성으로 제품 가설을 검증한다.

## 상태 처리

| 상태 | 앱 동작 |
|---|---|
| 입력 오류 | 요청 전에 필드 아래 안내 |
| 로딩 | 버튼 비활성화와 진행 표시 |
| 성공 | Safe·Balanced·Bold 세 전략과 근거 표시 |
| 빈 결과 | 조건을 몰래 완화하지 않고 수정 안내 |
| API 오류 | 원인 안내와 다시 시도 제공 |

## Mock 제거 조건

- 설문과 경쟁 분석으로 첫 구매 상황이 결정됨
- 사용 권한이 확인된 상품 피드 또는 파트너 API 확보
- 실제 필드의 출처·갱신 시각·이용 범위 저장 가능
- 합성 데이터와 운영 데이터가 테스트·로그에서 명확히 분리됨

## 현재 비목표

- 추천 정확도 또는 구매 전환 성과 주장
- 실제 브랜드 상품·이미지 수집
- 로그인, 결제, 주문, ERP 전체 기능
- 생성형 AI를 이용한 가격·재고·실측 생성
