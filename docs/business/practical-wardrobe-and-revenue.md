# FITWISE 실용적 옷장 가치와 수익 모델 v0

> 상태: 검증 전 사업 가설 · 기준일: 2026-10-14 · 제품 기준: `사지 않음`도 좋은 결과다

## 1. 제품 방향

FITWISE는 유행 상품을 더 많이 노출해 충동구매를 만드는 쇼핑 피드가 아니다. 사용자가 이미 가진 옷, 실제 생활에서 부족한 옷, 목적·예산·사이즈와 예상 활용도를 함께 확인해 **필요한 옷만 판단하도록 돕는 독립적인 의사결정 도구**다.

```text
더 많이 발견하기
  → 더 잘 고르기
  → 이미 있으면 사지 않기
  → 산다면 오래 입을 한 벌 고르기
```

설문 21건에서는 결정에 30분 이상 걸린 응답이 15명(71.4%), 플랫폼 밖에서 추가 비교를 한 응답이 20명(95.2%)이었다. 보유 의류 조합 정보는 4명(19.0%)이 가장 필요한 정보로 선택했다. 이 결과는 `비교와 판단` 문제를 지지하지만, FITWISE가 실제로 과소비를 줄인다는 증거는 아니다. 중복 구매 방지, `사지 않음` 수용성과 지불 의향은 후속 행동 테스트로 검증한다.

## 2. 사용자가 얻는 핵심 가치

| 판단 질문 | FITWISE가 제공할 근거 | 가능한 결과 |
|---|---|---|
| 정말 필요한가? | 옷장 공백, 목적, 계절, 착용 예정 | 구매 · 보류 · 사지 않음 |
| 비슷한 옷이 이미 있는가? | 카테고리·색상·핏·소재·용도 유사도 | 중복 경고와 보유 옷 제안 |
| 자주 입을 수 있는가? | 기존 옷과 가능한 조합, 예상 착용 상황 | 활용도와 주의점 |
| 예산에 맞는가? | 가격, 예산 잔여, 대체 후보 | 예산 적합도와 대기 선택 |
| 몸에 맞을 가능성이 있는가? | 상품 실측, 평소 사이즈, 근거 부족 상태 | 추천 사이즈와 신뢰도 |
| 지금 사야 하는가? | 필요도, 중복 위험, 데이터 최신성 | 즉시 구매보다 저장·재검토 허용 |

### 제안하는 결정 점수

상품 매출 가능성을 점수에 넣지 않는다. 추천 점수는 사용자 효용만으로 계산한다.

```text
need_score =
  occasion_need       × 0.25 +
  wardrobe_gap        × 0.25 +
  wardrobe_match      × 0.15 +
  size_confidence     × 0.15 +
  budget_fit          × 0.10 +
  expected_use        × 0.10 -
  duplicate_risk      × penalty
```

가중치는 구현 확정값이 아니라 프로토타입 검증용 가설이다. `need_score`가 낮거나 중복 위험이 높으면 추천 목록 위에 `새로 사지 않고 보유 옷 활용`을 표시한다.

## 3. 과소비 방지 기능 가설

### P0 흐름에 추가할 판단

1. 검색 조건에서 `왜 필요한지`, `언제 입을지`, `예산`을 확인한다.
2. 대표 보유 의류 3~5개와 유사도를 비교한다.
3. 유사 상품이 있으면 새 상품보다 먼저 중복 경고와 기존 옷 활용안을 보여준다.
4. 후보마다 `옷장 공백`, `조합 가능`, `중복 위험`, `예상 활용 상황`을 설명한다.
5. 최종 CTA를 `구매처 보기` 하나로 두지 않고 `사지 않음`, `보류`, `비교 저장`과 같은 수준으로 제공한다.

### P1 검증 후보

- 유사 보유 의류 묶음과 차이 설명
- 구매 전 24~72시간 재검토 알림
- 월 의류 예산과 구매 횟수 한도
- 착용 횟수와 구매가를 이용한 개인용 `회당 비용` 참고값
- 오래 입지 않은 옷의 재활용·기부·공식 리세일 경로 안내

환경효과나 절약액은 실제 측정 근거가 없으면 단정하지 않는다. 특히 `친환경` 표현은 실증 가능한 범위에서만 사용한다.

## 4. 수익 모델 원칙

수익이 추천 결과를 왜곡하면 FITWISE의 차별점이 사라진다. 다음 원칙을 모든 모델에 적용한다.

1. 수수료·광고비·브랜드 계약은 추천 점수와 순위를 변경하지 않는다.
2. `사지 않음`과 보유 옷 활용도 정상적인 최상위 결과가 될 수 있다.
3. 제휴·후원 관계는 추천과 구매 링크 가까이에 명확히 표시한다.
4. 무료 사용자에게도 추천 이유, 주의점, 데이터 출처와 삭제 권리를 제공한다.
5. 개인 옷장·신체·사진·행동 데이터를 판매하지 않는다.
6. 실제 상품은 권리가 확인된 피드·API로만 받고 가격·재고·실측의 갱신 시각을 표시한다.

## 5. 단계별 수익 모델

| 순서 | 모델 | 사용자가 지불하는 가치 | FITWISE 적합성 | 도입 조건 |
|---:|---|---|---|---|
| 1 | 프리미엄 구독 | 고급 옷장 분석, 중복·공백 리포트, 예산·활용도 추적, 더 긴 결정 이력 | 판매량과 무관해 독립성을 지키기 쉬움 | 반복 사용과 지불 의향 확인 |
| 2 | 선택 후 제휴 수수료 | 사용자가 구매를 결정한 뒤 공식 판매처로 안전하게 이동 | 무료 접근성을 유지할 수 있으나 이해충돌 관리 필요 | 추천 순위 분리, 경제적 관계 표시, 어트리뷰션 동의 |
| 3 | 1:1 스타일 상담 중개 | 사람 전문가의 옷장 진단과 목적별 제안 | 고관여 사용자의 명확한 서비스 가치 | 전문가 품질·환불·책임 범위 확정 |
| 4 | B2B API·SaaS | 쇼핑몰에 중복 경고, 옷장 조합, 사이즈 근거 모듈 제공 | 소비자 기능을 재사용할 수 있음 | 별도 계약, 테넌트 분리, 데이터 재사용 금지 |
| 5 | 공식 리세일·수선 연결 | 사지 않음 이후 기존 옷의 수명 연장 | 실용적 옷장 목표와 정렬 | 공식 파트너, 상태·책임·수수료 표시 |

### 권장 순서

- **MVP:** 결제 없이 상품 이동·보류·사지 않음 행동과 반복 사용 의향만 측정한다.
- **초기 수익화:** 구독 가치를 먼저 검증한다. 가격은 아직 정하지 않고 5인 테스트와 베타에서 기능별 지불 의향을 수집한다.
- **제휴 파일럿:** 사용자가 구매를 선택한 뒤에만 1~3개 공식 파트너 링크를 제공한다.
- **확장:** 소비자 제품의 품질과 데이터 경계가 검증된 뒤 B2B와 리세일을 별도 사업 실험으로 진행한다.

배너 광고, 미표시 스폰서 순위, 개인 데이터 판매와 브랜드가 구매한 추천 슬롯은 현재 모델에서 제외한다.

## 7. 사업성과 신뢰를 함께 보는 지표

### 제품 북극성 지표 후보

`근거를 확인하고 완료한 유효 결정 수`를 구매 여부와 무관하게 집계한다.

유효 결정은 사용자가 후보와 근거를 확인한 뒤 `구매`, `보류`, `사지 않음` 중 하나를 선택한 세션이다. 구매만 성공으로 계산하지 않는다.

### 사용자 가치

- 기존 방식 대비 결정 시간과 외부 이동 수
- 중복 경고를 보고 후보를 제외한 비율
- `사지 않음` 또는 보류 결정을 납득한 비율
- 추천 이유·주의점 이해도와 선택 확신도
- 보유 옷으로 만든 조합의 유용성
- 30일 뒤 실제 착용 여부와 후회 여부

### 사업성

- 7일·30일 재방문과 두 번째 유효 결정
- 구독 기능별 사용·지불 의향
- 구매를 선택한 세션의 판매처 이동률
- 표시된 제휴 관계 이해도
- 제휴 유무에 따른 추천 순위 일치율 100%
- 사용자 1명당 상품 데이터·AI·스토리지 비용

GMV, 클릭률과 구매 전환율을 단독 북극성 지표로 사용하지 않는다.

## 8. 다음 검증 실험

### 5인 사용성 테스트에 추가

1. 참가자가 이미 가진 옷과 유사한 후보를 최소 1개 포함한다.
2. `사지 않음` 결과와 구매 후보가 함께 있을 때 최종 선택과 이유를 기록한다.
3. 중복 경고 전후의 선택 확신도와 구매 의향 변화를 측정한다.
4. 제휴 표시가 있는 구매 링크가 추천 신뢰에 미치는 영향을 질문한다.
5. 다음 네 가지 중 지불할 가치가 있는 항목을 강제 선택한다: 고급 옷장 분석, 예산·활용도 리포트, 사람 스타일 상담, 없음.

### 통과 기준 초안

| 가설 | 통과 신호 | 실패 시 조치 |
|---|---|---|
| 중복 경고가 유용하다 | 4/5가 차이를 이해하고 결정에 반영 | 유사도 설명과 입력 부담 재설계 |
| 사지 않음도 신뢰를 만든다 | 4/5가 강매가 아닌 도움으로 인식 | 문구·근거·CTA 우선순위 수정 |
| 반복 가치가 있다 | 4/5가 다음 구매 전 재사용 상황을 구체적으로 설명 | 옷장 기능 우선순위 재검토 |
| 수익화가 신뢰를 해치지 않는다 | 5/5가 제휴 관계를 인지하고 순위 독립성을 설명 | 제휴 모델 보류 |

표본 5명은 학습용 사용성 검증이며 시장 규모나 가격 결정의 통계적 근거로 사용하지 않는다.

## 9. 구현·데이터 요구사항

- `decision_outcome`: `buy`, `hold`, `no_purchase`
- `duplicate_risk`: 점수, 비교한 wardrobe item ID, 근거 버전
- `wardrobe_gap`: 부족 카테고리·용도와 계산 버전
- `commercial_relation`: `none`, `affiliate`, `sponsored`와 표시 문구
- 추천 점수와 상업 점수를 별도 테이블·서비스에 보관하고 상업 점수를 랭킹 API 입력에서 차단
- 가격·재고·상품 정보에 `source`, `observed_at`, `expires_at` 저장
- 분석 이벤트는 개인 원문 대신 비식별 결과 코드와 동의 버전만 저장
- 구독·제휴·B2B는 각각 별도 Issue와 위협 모델을 승인한 뒤 구현
