# 상품 카탈로그와 추천 점수 설계

상태: 설계 초안 · 실제 상품 연동 전 검증 필요

## 목적과 원칙

FITWISE는 많이 구매하도록 유도하기보다, 사용자가 필요한 품목과 예산을 정리하고 이미 가진 옷과 중복되지 않는 선택을 돕는다. 초기 추천은 재현성과 설명 가능성을 위해 규칙 기반으로 계산한다. 언어 모델은 필수 구성요소가 아니다.

## 현재 UX 프로토타입

- 합성 품목 30개: 상의 10개, 하의 10개, 구두 10개
- 검색어에서 격식/캐주얼, 색상, 계절, 편안함, 관리 편의 조건을 읽고 각 품목 점수를 계산해 순위화
- 상의·하의·구두 각각 1개를 선택하고 합계가 500,000원 이하인지 계산
- 소재·색상·계절·가격 등은 시연용 가상값이며 실제 상품 설명이나 판매가가 아님
- 선택과 확신도는 브라우저 메모리에서만 유지. 서버 전송·저장 없음
- 프로토타입은 검색 로직 설명과 사용 흐름 확인용이다. 정확도나 시장 규모를 입증하지 않는다.

## 데이터 모델 초안

제품과 사이즈/색상 선택지(variant)를 분리한다.

| 필드 | 설명 |
|---|---|
| product_id / variant_id | 내부 불변 식별자 |
| category | top, bottom, shoes 등 통제된 분류 |
| name / brand | 상품명과 브랜드. 미확인 값은 추정하지 않음 |
| price / currency | 현재 가격, 통화, 가격 확인 시각 |
| colors / sizes | 표준화된 색상과 사이즈 변형 |
| formality / season / style | 추천에 쓰는 정규화 속성 |
| material / fit / care | 소재, 핏, 관리 정보 |
| tags | 용도·스타일·기능을 나타내는 통제된 태그 |
| stock_status | 판매 가능 여부와 마지막 확인 시각 |
| product_url / image_url | 출처 링크와 이미지 위치 |
| source / rights / fetched_at | 제공처, 사용 권한 근거, 수집 시각 |

필수 정보가 비어 있거나 오래된 가격·재고는 근거 수준을 낮추고, 구매 직전 다시 확인하도록 표시한다. 재고 없음 상품은 기본 결과에서 제외한다.

## 검색·순위·조합 흐름

1. 사용자의 문장을 구조화한다: 필요한 품목, 상황 격식, 색상, 계절, 예산, 편안함/관리 조건.
2. 품목과 예산, 명시적 제외 조건으로 후보를 필터링한다.
3. 설명 가능한 점수를 계산한다: 상황 격식 일치, 색상/계절 일치, 편안함/관리 특성, 가격 부담, 데이터 신선도.
4. 각 점수의 기여 이유를 사용자에게 보여준다. 해당 정보가 없으면 확정적으로 추론하지 않는다.
5. 상의·하의·구두 조합에서는 한 품목씩 선택할 때 총액과 잔액을 계산한다. 총 예산을 넘으면 완료할 수 없게 하고 더 저렴한 후보를 제시한다.
6. 적합한 조합이 없으면 억지 추천하지 않고 예산·조건 조정 선택지를 제시한다.
7. 비슷한 후보만 반복되지 않도록 가격대, 색상, 활용도에 따라 결과를 다양화한다.

실제 가중치와 임계치는 임의로 확정하지 않는다. 익명 사용자 테스트와 품목별 성공/오류 관찰에 따라 조정하고 변경 근거를 기록한다.

## 실제 상품 데이터 출처

1. 우선순위: 브랜드/판매처 공식 상품 피드 또는 제휴 API와 사용 허가가 확인된 데이터.
2. 출처별 이용약관, 이미지/설명 재사용 권한, 가격·재고 갱신 주기, API 호출 제한을 확인하고 기록한다.
3. 허가되지 않은 페이지 수집이나 이미지 복제는 기본 데이터 파이프라인으로 사용하지 않는다.
4. 초기 실험은 합성 상품 데이터로 계속 진행한다. 외부 데이터 제공처와 이용 권한이 확정되기 전 실제 상품 연동 완료로 표시하지 않는다.
5. 상품 데이터는 출처·시각·권한을 저장하고, 오래되거나 삭제된 상품을 갱신/제외하는 절차를 둔다.

## 대량 데이터와 성능

- 정규화된 제품/variant 저장, 카테고리·가격·판매상태 복합 인덱스, 표준화 태그 인덱스를 사용한다.
- 결과는 페이지 단위로 가져오고 이미지 썸네일/지연 로딩과 캐시를 적용한다.
- 전체 카탈로그를 클라이언트로 내려보내지 않는다. 검색과 필터는 서버에서 수행한다.
- 상품 동기화는 백그라운드 작업으로 분리하고 중복 수집, 실패 재시도, 오래된 데이터 경보를 기록한다.
- 실제 운영 전 검색 지연, 결과 수, 캐시 적중률, 오래된 가격/재고 비율을 측정한다.

## 보안·개인정보

- 검색어에 이름·연락처 등 개인정보를 입력하지 않도록 안내한다.
- 실제 저장 단계에서 검색어와 옷장 데이터의 보관 기간, 사용자 삭제 요청, 접근 권한, 암호화, 백업 복구 정책을 별도 설계한다.
- 계정별 옷장/검색 기록은 서버에서 사용자 소유권을 검증한다(RLS 포함). 비밀 키는 클라이언트에 넣지 않는다.
- 테스트용 가상 데이터와 운영 상품 데이터를 분리하고, 실제 사용자 동의 없이 개인 옷장 정보를 추천 학습에 쓰지 않는다.

## 다음 검증

- 같은 조건에서 상의·하의·구두를 각각 선택해 총 500,000원 이내 조합을 만들 수 있는가?
- 결과 순위의 이유를 사용자가 이해하고, 예산 초과나 조건 불일치가 분명하게 안내되는가?
- 실제 상품 연동 전에 제공처별 권리·갱신주기·품질 기준을 승인했는가?
