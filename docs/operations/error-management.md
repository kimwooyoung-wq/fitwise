# Error Management

## 목적

FITWISE의 오류를 한곳에서 발견하고, 재현하고, 우선순위를 정하고, 같은 PR에서 수정·재검증한다. GitHub Issue와 PR이 원본이며 Notion의 Error Center는 개인용 요약판이다.

## 오류 흐름

```text
앱·API·CI에서 발견
  → 개인정보 제거
  → 기존 Issue 검색
  → 재현 가능하면 Issue 등록
  → 심각도·영역·상태 분류
  → 기존 브랜치/PR에서 수정
  → 회귀 테스트
  → PR 증빙 갱신
  → 사용자 최종 확인 후 종료
```

## 기록 위치

| 정보 | 기준 위치 | Notion 표시 |
|---|---|---|
| 재현 절차·로그·원인 | GitHub Issue | 건수·심각도·링크 |
| 코드 변경·테스트·증빙 | GitHub PR | 상태·PR 링크 |
| CI 실행 결과 | GitHub Actions | 성공/실패 요약 |
| 실제 앱 오류 | Sentry, 베타 전 도입 | 미해결 건수·최신 사건 |
| 일정·담당·막힌 점 | Notion | 개인 대시보드 |

Notion에 스택 트레이스, 토큰, 검색 원문, 신체정보 또는 사용자 사진을 복사하지 않는다.

## 분류 기준

### 심각도

| 등급 | 기준 | 대응 |
|---|---|---|
| `severity/critical` | 개인정보 노출, 인증 우회, 데이터 손상 | 기능 중지·즉시 조사 |
| `severity/high` | 핵심 검색→추천 흐름을 완료할 수 없음 | 다른 기능보다 우선 수정 |
| `severity/medium` | 우회 가능하지만 결과·상태가 잘못됨 | 현재 주기 안에 수정 |
| `severity/low` | 문구·정렬·경미한 시각 문제 | 백로그에서 묶어 처리 |

### 영역

`area/mobile`, `area/api`, `area/data`, `area/recommendation`, `area/infra`, `area/docs`

### 상태

`status/needs-triage`, `status/reproduced`, `status/in-progress`, `status/needs-verification`, `status/blocked`

## Issue 최소 양식

```text
제목: [영역] 사용자가 겪는 실패

환경: 앱 버전 / OS / API 버전
사전 조건:
재현 절차:
기대 결과:
실제 결과:
재현 빈도:
영향 범위:
개인정보 제거 증빙:
관련 PR 또는 로그 링크:
```

오류 메시지는 사용자 입력 전체를 포함하지 않고 `request_id`, 오류 코드, 앱·API 버전만 기본 수집한다.

## 화면 상태 체크

모든 화면 PR은 다음 상태를 확인한다.

- 로딩: 중복 제출 차단, 진행 상태 안내
- 빈 결과: 조건을 몰래 바꾸지 않고 수정 방법 안내
- 입력 오류: 잘못된 필드 가까이에 해결 방법 표시
- 네트워크/API 오류: 안전한 문구, 다시 시도, 요청 ID
- 재시도: 이전 오류가 사라지고 동일 요청이 중복 저장되지 않음
- 오프라인: 캐시 데이터와 최신 데이터가 명확히 구분됨

## Sentry 도입 조건

비공개 베타 전 다음 조건을 만족할 때 앱과 API 오류 수집을 연결한다.

- 개발·스테이징·운영 환경 분리
- source map과 release 버전 연결
- 토큰, 검색 원문, 신체정보, 사진 URL 마스킹
- 사용자 식별자는 내부 난수 ID만 사용
- 표본 비율과 보존 기간 문서화
- 테스트 오류를 전송해 Issue 생성·해결 흐름 검증

## 현재 기준선

| 항목 | 상태 |
|---|---|
| Mobile CI | 통과 |
| API CI | 통과 |
| 열린 런타임 오류 | 확인된 항목 없음 |
| 의존성 경고 | npm transitive audit 28건 — 10 moderate, 18 high |
| 실기기 검증 | 사람 확인 필요 |
| Sentry | 베타 전 도입 예정 |

의존성 경고는 실제 취약 경로인지 별도 검토하기 전까지 런타임 오류와 동일하게 세지 않는다. 호환성을 깨는 강제 업데이트는 하지 않고 Expo 호환 버전과 실제 사용 경로를 먼저 확인한다.
