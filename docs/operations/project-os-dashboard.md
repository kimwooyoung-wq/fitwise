## GitHub·Notion 상태 정합성 점검

GitHub `main`, 열린 Issue, Pull Request, CI와 저장소 작업 문서를 원본으로 삼고 Notion과 Project OS는 그 결과를 요약해 표시한다. 완료 여부는 문구가 아니라 검증 증빙으로 판정한다.

### 완료 판정 기준

- **완료**: 완료 조건 충족, 필요한 검사 성공, 증빙 기록, PR 반영까지 확인된 작업
- **진행 중**: 구현 체크리스트가 끝났더라도 PR 병합 전이거나 실기기 확인·사용자 승인 같은 필수 조건이 남은 작업
- **보완 필요**: 테스트 실패, 리뷰 의견, 누락된 증빙, 깨진 링크 또는 GitHub와 Notion의 상태 불일치가 있는 작업
- **미정**: 목표·완료 조건·시작 일정 중 하나 이상이 확정되지 않은 작업

### 반복 점검 항목

1. GitHub Issue 체크리스트와 연결 PR 상태를 확인한다.
2. PR의 CI, 테스트 수, 경고, 사람 확인 항목과 남은 작업을 확인한다.
3. Notion과 Project OS의 완료·진행·미정 표시를 GitHub 근거와 대조한다.
4. 완료 증빙이 있는데 미완료로 남은 항목과, 증빙 없이 완료된 항목을 바로잡는다.
5. 누락 과제, 오류 기록, 깨진 링크, 오래된 백업 날짜와 테스트 결과를 기록한다.
6. 수정 후 GitHub 문서·PR과 Notion에 동일한 상태와 증빙 링크를 남긴다.

PR 병합, Issue 종료, 브랜치 삭제와 운영 데이터 변경은 사용자 승인 없이 자동 처리하지 않는다. 상태 변화가 없으면 기록을 반복 생성하지 않고, 의미 있는 불일치·수정·실패·사용자 확인 필요 사항만 보고한다.

## 현재 제한사항

1. GitHub API가 차단된 환경에서는 자동 갱신 대신 점검 시점의 백업 데이터를 사용한다.

4. Issue 상태 분류 품질을 유지하려면 각 저장소에서 진행 상태 라벨을 일관되게 사용해야 한다.
