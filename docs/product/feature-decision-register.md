# 기능 결정 등록부

> 상태: 설문 21건 기준선 · 경쟁 과업과 5인 사용성 테스트 후 갱신
> 기준일: 2026-10-13
> 원칙: 아이디어 수가 아니라 사용자 문제, 증거, 데이터 권리와 검증 비용으로 결정한다.

## 목적

현재 기능, 빠진 기능과 새 아이디어를 한 곳에서 검토한다. 설문에 많이 등장했다는 이유만으로 바로 구현하지 않고 다음 다섯 조건을 확인한다.

1. 설문 또는 관찰에서 반복된 실제 문제인가?
2. 핵심 흐름 `상황·예산 → 조건 확인 → 3개 후보 → 사이즈·핏 근거 → 비교`를 직접 개선하는가?
3. 사용성 테스트로 효과를 판정할 수 있는가?
4. 합법적이고 최신인 데이터로 구현할 수 있는가?
5. 개인정보·성능·운영 비용이 가치보다 크지 않은가?

## 설문에서 확정된 문제

| 관찰 | 결과 | 제품 결정 |
|---|---:|---|
| 결정에 30분 이상 사용 | 15/21, 71.4% | 결정 시간과 외부 이동 감소를 핵심 지표로 사용 |
| 사이즈·핏이 가장 어려움 | 7/21, 33.3% | 근거·누락 데이터·신뢰도를 P0로 제공 |
| 여러 후보 비교가 가장 어려움 | 6/21, 28.6% | 서로 다른 전략의 후보 3개를 같은 기준으로 비교 |
| 플랫폼 밖 추가 행동 | 20/21, 95.2% | 흩어진 근거를 한 흐름에 모으되 출처 이동은 보존 |
| 유사 체형 후기가 가장 필요 | 7/21, 33.3% | 필요성은 강하지만 동의·익명화·표본 품질 전까지 P2 |
| 옷장 조합 정보 필요 | 4/21, 19.0% | 태그형 최소 옷장으로 P1 검증 |
| 가격·할인 정보 필요 | 4/21, 19.0% | 최신 시각·출처가 있는 경우에만 P1 제공 |

표본은 21명의 편의표본이고 실제 행동·지불 의향을 측정하지 않았다. 따라서 기능 효과와 시장성을 확정한 결과가 아니다.

## 기능별 결정

| 기능 | 상태 | 근거 | 현재 범위 | 다음 통과 조건 |
|---|---|---|---|---|
| 상황·예산 자연어 입력 | P0 유지 | 구매 상황이 목적·활동·격식·계절로 반복 | 입력과 검증 오류 | 4/5가 도움 없이 조건 입력 |
| 구조화 조건 확인·수정 | P0 유지 | 자연어만으로 필수 조건을 보장할 수 없음 | 추천 전 명시적 확인 | 잘못 파싱된 조건을 4/5가 수정 |
| Safe·Balanced·Bold 3개 후보 | P0 유지 | 후보 비교 문제 28.6% | 필수 조건을 지킨 소수 후보 | 4/5가 전략 차이를 설명 |
| 사이즈·핏 근거와 부족 상태 | P0 유지 | 어려움 1위, 유사 체형 근거 요구 1위 | 실측·누락·주의점·신뢰도 | 5/5가 부족 상태를 확정 추천으로 오해하지 않음 |
| 동일 기준 비교 보드 | P0 유지 | 외부 비교 행동과 후보 비교 문제 | 가격·목적·사이즈·주의점 | 기존 방식보다 시간·외부 이동 중앙값 감소 |
| 로딩·빈 결과·오류·재시도·오프라인 | P0 유지 | 안전한 완료를 위한 필수 상태 | 입력 보존과 중복 방지 | 상태별 UI·계약 테스트 통과 |
| 추천 출처·최신 시각 | P0 보완 | 가격·실측을 AI가 생성하면 안 됨 | 근거마다 출처와 관찰 시각 | 출처 없는 사실 0건 |
| 저장·제외·취소 | **P1로 조정** | 설문이 반복 사용을 검증하지 않음 | P0 테스트 후 명시적 피드백 | 4/5가 필요성을 설명하거나 재사용 의향 확인 |
| 대표 옷 3~5개 태그 등록 | P1 유지 | 옷장 조합 요구 19.0% | 사진 없이 최소 필드 우선 | 조합 판단 도움 4/5, 재사용 의향 확인 |
| 조합 가능성·중복 위험 | P1 유지 | 옷장 보완 구매와 조합 요구 | 결정 근거로만 표시 | 기존 방식보다 후보 제외 이유가 명확해짐 |
| 구매·보류·사지 않음 결정 | P1 신규 후보 | 중복 구매 방지와 독립적 판단이라는 제품 가설 | 동일 수준 CTA와 결정 이유 코드 | 4/5가 강매가 아닌 도움으로 인식 |
| 구매 전 재검토 | P1 신규 후보 | 유행·충동보다 실제 필요를 확인하는 가설 | 24~72시간 보류와 재확인 | 재확인 후 결정 이유가 명확하고 불편 과다 없음 |
| 가격·할인·판매처 이동 | P1 유지 | 가격 요구 19.0%, 사업성 가설 미확정 | 허가된 카탈로그에서만 제공 | 최신성 오류 0건, outbound 행동 관찰 |
| 비교 기준 중요도 조정 | 검증 후보 | 개인마다 가격·핏·스타일 우선순위가 다름 | 프로토타입 A/B에서만 | 순위 조정 이해 4/5, 결정 시간 악화 없음 |
| 유사 체형 후기 요약 | P2 유지 | 요구 33.3%이나 민감정보·표본 편향 위험 | 합성 평가셋 외 운영 금지 | 명시적 동의·익명화·최소 표본·편향 검토 |
| 데이터 오류 신고 | P1 신규 후보 | 잘못된 가격·실측은 추천 안전을 훼손 | 상품·근거 단위 신고 | 신고가 원본 출처와 연결되고 운영자가 재현 가능 |
| 추천 이유 피드백 | P1 신규 후보 | 설명 가능성 효과가 아직 미확정 | 도움 됨/안 됨과 이유 코드 | 근거 개선으로 연결 가능한 비식별 이벤트 |

## 의도적으로 넣지 않는 기능

| 기능 | 결정 이유 | 재검토 조건 |
|---|---|---|
| 얼굴·전신 사진 체형 자동 추정 | 민감정보·편향·오판 위험이 핵심 가치보다 큼 | 별도 동의와 안전성·필요성 근거 확보 |
| 모든 쇼핑몰 상품·리뷰 크롤링 | 권리·최신성·운영 비용 문제 | 정식 파트너 피드·API 계약 |
| 앱 안 결제·주문·반품·전체 ERP | 최종 판단 지원이라는 현재 문제를 벗어남 | 자체 거래 사업 모델과 운영 책임 검증 |
| 무한 피드·SNS·커뮤니티 | 결정 시간을 줄이는 목표와 충돌 가능 | 행동 검증에서 공동 판단이 핵심으로 확인 |
| 가격·재고·실측 AI 추정 | 허위 사실이 구매 피해로 연결 | 재검토하지 않음; 구조화 원본만 사용 |
| AR 가상 착용 | 구현·데이터 비용이 크고 설문 근거 없음 | P0·P1 효과 검증 후 별도 연구 |
| 위치·날씨 상시 수집 | 정확한 위치가 핵심 과업에 불필요 | 사용자가 직접 선택한 지역·날씨가 반복 요구될 때 |
| 자동 구매·쇼핑몰 계정 연동 | 보안·약관·결제 위험과 범위 확대 | 파트너 계약과 명시적 사용자 승인 체계 |

## 빠진 기능 감사 결과

새 제품 영역을 늘리는 대신 현재 흐름에 필요한 다음 공통 기능을 요구사항에 보강한다.

1. **근거 출처·최신 시각**: 추천 문장과 가격·실측이 어느 데이터에서 왔는지 확인한다.
2. **데이터 오류 신고**: 잘못된 가격·재고·사이즈를 추천 피드백과 분리해 수정 흐름으로 연결한다.
3. **데이터 삭제·캐시 정리 결과**: 계정 삭제 시 서버·스토리지·기기 캐시 처리 상태를 확인한다.
4. **접근성 있는 비교표**: 색상만 사용하지 않고 스크린리더와 글자 확대에서도 비교가 가능해야 한다.
5. **성능 보호 장치**: 목록 hard limit, pagination, 썸네일과 성능 회귀 검사를 기능 완료 조건에 포함한다.

이 중 1·3·4·5는 품질과 안전에 필요한 기능이므로 설문 빈도와 무관하게 필수다. 2는 P1 후보로 두고 운영 가능성을 먼저 확인한다.

## 변경 규칙

새 기능을 제안할 때 Issue에 다음을 적는다.

- 연결된 설문·관찰·테스트 근거
- 해결할 사용자 행동과 성공·실패 지표
- P0 흐름에 미치는 영향
- 필요한 데이터의 출처·권리·최신성
- 개인정보·보안·성능·운영 비용
- 구현하지 않을 경우의 영향
- 채택, 보류, 제외 중 제안 상태

5인 사용성 테스트 전에는 P0 제품 영역을 추가하지 않는다. 테스트 후에도 4/5 성공, 안전 기준과 데이터 권리를 만족하지 못한 기능은 일정 때문에 강행하지 않는다.
