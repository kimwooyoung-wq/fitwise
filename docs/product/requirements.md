# FITWISE 제품 요구사항 기준선

> 상태: v0 · 4주차 사용자 검증 후 목표값과 P1 범위를 확정한다. 이 문서가 있다는 사실은 PRD 게이트 통과를 의미하지 않는다.

## 1. 대상 사용자와 대표 과업

- 대상: 온라인에서 의류를 구매하며 사이즈·핏 또는 후보 비교에 어려움을 겪는 20~30대 사용자
- 대표 과업: `15만 원 이하의 회사 워크숍용 상의 또는 아우터를 찾고, 검은색 슬랙스와 어울리는 후보를 비교해 하나를 선택한다.`
- 핵심 결과: 더 많은 상품이 아니라 사용자가 선택할 수 있는 근거를 제공한다.

## 3. 상태 요구사항

모든 P0 화면은 다음 상태를 별도 UI와 테스트로 제공한다.

- 로딩: 진행 상태와 중복 제출 방지
- 빈 결과: 이유와 조건 수정 경로
- 검증 오류: 문제가 있는 입력과 해결 방법
- 서버·네트워크 오류: 재시도와 입력 보존
- 낮은 신뢰도: 부족하거나 충돌한 데이터와 추가 확인 방법
- 오프라인: 가능한 동작과 불가능한 동작 구분

## 5. 측정 이벤트 초안

| 이벤트 | 목적 | 금지 데이터 |
|---|---|---|
| `search_submitted` | 조건 입력 완료와 시작점 측정 | 자연어 원문, 신체정보 원문 |
| `recommendations_viewed` | 후보 노출과 빈 결과 측정 | 운영 상품 전체 응답 |
| `evidence_opened` | 근거·주의점 확인 행동 | 사용자 사진 |
| `candidate_selected` | 결정 완료율과 시간 측정 | 구매·결제 정보 |
| `outbound_clicked` | 제휴 가능성 탐색 | 외부 계정 식별자 |
| `wardrobe_linked` | 구매 후 연속성 탐색 | 이미지 URL·세부 신체정보 |

이벤트 명칭, 속성, 기준선과 목표값은 4주차 `analytics-plan.md`에서 확정한다.

## 6. 요구사항 추적

모든 구현 Issue와 PR은 하나 이상의 요구사항 ID를 적는다. 요구사항이 없는 기능은 범위 변경 검토를 먼저 진행한다. 테스트 또는 증빙이 없는 요구사항은 `완료`로 표시하지 않는다.
