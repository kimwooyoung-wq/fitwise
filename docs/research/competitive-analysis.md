> 상태: 대상·시나리오 확정 / 공개 웹 1차 관찰 완료 / 동일 과업 실측 미완료  
> 기준일: 2026-10-13  
> 관련 가설: H-02, H-03, H-04, H-05, H-07

## 1. 검증 목적

대형 패션 플랫폼의 기능 수를 비교하거나 모방 대상을 고르는 조사가 아니다. 사용자가 상황·예산·사이즈·보유 의류 조건을 함께 고려해 하나를 결정할 때 기존 서비스 밖으로 이동하는 지점과 FITWISE가 연결할 의사결정 단계를 찾는다.

## 3. 고정된 테스트 환경

- 조사일: 2026-10-13부터 동일 과업 실측 종료일까지
- 지역·통화: 대한민국, KRW
- 최초 조건: 로그아웃 공개 화면. 로그인이 필요하면 그 시점과 요구 데이터를 기록한다.
- 예산: 최대 150,000원
- 상품 범위: 검은색 슬랙스와 조합할 상의 또는 가벼운 아우터
- 성별·체형: 테스트 참여자가 자신의 조건을 사용하되 서비스가 요청한 항목만 기록한다.
- 개인정보: 계정명, 연락처, 주문 내역, 정확한 신체 치수는 캡처·공개 문서에 남기지 않는다.

## 4. 공통 과업

```text
예산 15만 원으로 회사 워크숍에 입을 옷을 찾는다.
너무 격식 있지 않아야 하며 보유한 검은색 슬랙스와 조합해야 한다.
사이즈와 추천 이유를 확인하고 하나의 후보를 결정한다.
```

## 5. 실행 절차

1. 서비스 홈에서 시작하고 타이머를 시작한다.
2. 자연어 전체 조건을 한 번에 입력해 본다.
3. 지원되지 않으면 검색어·카테고리·필터 조합으로 조건을 옮긴다.
4. 상품 상세는 최대 5개까지 연다.
5. 사이즈·핏·후기·추천 이유·주의점과 데이터 한계를 찾는다.
6. 후보는 최대 3개를 같은 기준으로 비교한다.
7. 하나를 선택하거나, 근거가 부족해 안전하게 결정할 수 없다고 기록한다.

### 2026-10-13 공개 근거

- MUSINSA 카테고리 공개 화면에서 가격·사이즈·핏·스타일·후기/좋아요 필터와 상품별 가격을 확인했다. 공개 상품 화면에서 가격과 후기 수를 확인했지만 복합 자연어 의도와 보유 의류 조합은 확인하지 못했다.
- 29CM 공개 홈에서 카테고리, 콘텐츠형 컬렉션, 상품·가격 진입점과 앱 설치 유도를 확인했다. 동일 기준 후보 비교와 사이즈 판단 흐름은 아직 실측하지 않았다.
- SSF SHOP 공식 FAQ에서 실측·신체/평소 사이즈 후기 필터, 회원 사이즈 기반 일부 상품 추천과 구매·찜 상품 비교 안내를 확인했다. 상품별 제공 범위와 공통 과업 성공 여부는 수동 실측이 필요하다.
- Zigzag 공개 홈은 확인됐고, ABLY 공식 주소는 모바일 사이트로 연결됐다. W CONCEPT 공개 자동 확인은 제한됐다.

### 기능 패턴과 FITWISE의 대응

| 공개 패턴 | 배울 점 | 그대로 복제하지 않는 이유 |
|---|---|---|
| MUSINSA의 가격·사이즈·핏·스타일 필터 | 자연어를 검증 가능한 구조화 조건으로 변환 | 필터 수를 늘리는 것이 최종 결정 지원과 같지 않음 |
| 29CM의 에디터 맥락과 추천 상품 | 상황과 스타일을 상품 근거에 연결 | 콘텐츠 소비가 사이즈·후보 비교 문제를 해결하는지는 미검증 |
| SSF SHOP의 실측·체형 후기·구매/찜 비교 | 사용자의 기존 기준과 상품 치수를 연결 | 민감정보 최소 수집과 서비스별 데이터 품질 검증 필요 |
| Zigzag의 색상·사이즈 옵션 및 판매자 품질 정책 | 공급자 단계 필수 필드와 격리 규칙 | 공개 정책은 실제 추천 정확도나 앱 사용성을 증명하지 않음 |
| ABLY 공개 자료의 행동 기반 개인화 | 피드백이 추천 개선에 연결되는 루프 | 설문은 암묵 추적 동의를 검증하지 않아 명시적 피드백부터 시작 |

공개 화면과 판매자 자료는 기능 존재 여부를 확인하는 참고 근거일 뿐이다. 내부 추천 알고리즘, 데이터 규모, 성능 구조는 공개 자료 없이는 추정하지 않는다. 최종 채택 판단은 [기능 결정 등록부](../product/feature-decision-register.md)에서 관리한다.

공개 페이지의 존재나 일부 기능 노출을 동일 과업 성공으로 계산하지 않는다. 앱·로그인·개인 조건이 필요한 남은 관찰은 [사람 검증 실행표](human-validation-runbook.md)에 따라 수행한다.

## 8. FITWISE 차별화 가설과 반증 조건

**가설:** FITWISE는 한 플랫폼 안의 상품 발견을 늘리는 대신, 상황·예산·사이즈 근거·보유 의류 조건을 한 번에 구조화하고 세 후보를 같은 기준으로 설명해 최종 선택을 돕는다.

**반증 조건:** 6개 중 4개 이상에서 복합 의도를 한 번에 입력하고, 세 후보를 같은 기준으로 비교하며, 사이즈 근거와 보유 의류 맥락까지 한 흐름에서 확인할 수 있다면 현재 차별화 가설을 폐기하거나 다시 작성한다.

## 9. 사업성 가설

무료 의사결정 지원으로 후보 선택이 빨라지고 추천 결과의 외부 상품 이동이 발생하면 제휴 수수료 가능성을 먼저 검증한다. 판매 수수료가 추천 순위나 설명을 왜곡해서는 안 되며, 제휴 여부와 추천 기준을 분리해 표시한다. 구독과 B2B는 반복 사용과 판매자 문제 근거가 생기기 전에는 구현하지 않는다.
