# FITWISE 사용성 테스트 1차 실행 키트

상태: 실행 준비 초안  
연결 Issue: [#7](https://github.com/kimwooyoung-wq/fitwise/issues/7)  
실행 기간: 2026-11-19 ~ 2026-11-25 (참가자 모집 일정에 따라 조정)  
참가자 목표: 5명, 서로 다른 익명 코드 사용

> 이 문서는 테스트 프로토콜과 빈 양식입니다. 프로토타입 링크는 준비되었지만 참가자 테스트는 아직 실행되지 않았으며, 결과 칸을 임의로 채우지 않습니다.

## 현재 참가자용 프로토타입

- 테스트 화면: https://fitwise-wardrobe-test-wooyoung.w00young09111.chatgpt.site
- 화면은 옷장 데모가 아니라 면접 상황의 검색→추천 조합 프로토타입입니다. 상의·하의·구두 각 10개의 합성 후보를 상황·격식·색상·계절·편안함·관리 조건으로 점수화해 보여주며, 각 품목에서 1개씩 고르면 합계와 50만 원 예산 잔액을 계산합니다.
- 후보 30개(상의·하의·구두 각 10개)는 모두 합성 예시입니다. 순위는 격식, 색상, 계절, 편안함, 관리 편의 및 가격을 사용하는 설명 가능한 규칙 점수이며 AI 추천이 아닙니다. 실상품·실재고·실가격·상품 출처/권리·결제·계정·백엔드·DB/RLS는 검증하지 않습니다. 선택과 확신도는 브라우저 메모리에만 머물고 서버로 전송되지 않습니다. 세션 기록은 진행자가 이 문서 양식에 익명으로 수기 기록합니다.
- 같은 과제를 모든 참가자에게 읽고, 화면 조작을 설명하거나 결과를 유도하지 않습니다. 프로토타입 자체 결과를 실제 구매 근거나 상품 추천으로 해석하지 않습니다.
- 참가자용 링크는 초대된 계정만 접근하는 기존 제한 공개 설정을 유지합니다. 현재 테스트 대상 4명으로 파일럿을 시작할 수 있으며, Issue #7의 5명 목표를 채우려면 1명 추가 초대가 필요합니다.
- 프로토타입 배포는 준비되었지만, 참가자 세션은 아직 0/5이며 결과는 미측정입니다.

## 사전 점검 수정 이력 (참가자 결과 아님)

- 초기에 상의 위주 후보만 표시되어 사용자가 구두와 하의를 찾는 상황을 반영하지 못했고, 확신도 선택 뒤 완료 버튼도 없었습니다. 예산 역시 한 품목 기준으로만 다뤘습니다.
- 상의·하의·구두 각 10개, 총 30개 합성 후보로 확대했습니다. 입력 상황·격식·계절·편안함·관리 편의에 더해 색상은 가까이 언급된 품목에만 적용하도록 수정했습니다(‘검정 슬랙스’는 상의 색상을 검정으로 강제하지 않음).
- 품목별 하나씩 선택하고 총액/잔액을 확인하며, 합계 500,000원 이하일 때만 완료하도록 했습니다. 확신도 선택 후 조합 완료 화면과 진행자에게 결과를 알리는 안내가 나타납니다.
- 확인: 인라인 JavaScript 구문 검사 통과, 카탈로그 30개/품목별 10개/ID 중복 없음, 면접·화이트 셔츠·검정 슬랙스 검색의 상의·하의·구두 우선순위 확인, 257,000원 조합 통과 및 527,000원 조합 초과 사례 확인.
- 이 확인은 규칙과 화면 흐름의 사전 점검입니다. 브라우저 실사용 세션은 별도이며 참가자 테스트는 아직 0/5입니다.



## 1. 검증 질문

- 사용자는 구매 상황을 입력하고 후보를 비교해 최종 선택까지 설명 없이 완료할 수 있는가?
- 추천 이유, 주의점, 신뢰도, 보유 의류 조합 근거를 이해하는가?
- 어느 단계에서 오류, 되돌아가기, 도움 요청이 발생하는가?
- 결정 후 선택 확신도가 달라지는가?

## 2. 참가자 보호와 기록 규칙

- 시작 전에 목적, 예상 소요 시간, 기록 항목, 중단 가능성을 설명하고 동의를 받습니다.
- 녹화·녹음은 별도 동의를 받을 때만 합니다. 거절해도 참여에 불이익이 없습니다.
- 이름, 이메일, 계정, 얼굴, 신체 치수, 구매 이력 등 식별·민감 정보는 수집하지 않습니다.
- 결과는 P01~P05처럼 무작위 코드로 기록합니다. 인용문도 개인을 알아볼 수 없도록 요약하거나 비식별화합니다.
- 원본 기록 접근자는 프로젝트 책임자로 제한하고, 분석·설계에 필요한 익명 요약만 저장소에 남깁니다.
- 참가자가 동의를 철회하면 연결 가능한 원본 기록을 삭제합니다. 보관·삭제 날짜와 책임자는 세션 시작 전에 정하고 참가자에게 알립니다.
- 실제 상품·리뷰 데이터 대신 사용 권한이 확인된 자료나 합성 프로토타입 데이터를 사용합니다.

## 3. 세션 프로토콜 (약 20분)

### 시작 안내문

“FITWISE의 구매 결정 흐름을 확인하려고 합니다. 제품을 평가하는 것이 아니라 화면과 흐름을 평가합니다. 생각나는 점을 소리 내어 말해주시고, 원하시면 언제든 중단할 수 있습니다. 별도 동의가 없으면 화면을 녹화하지 않고 익명 메모만 남깁니다.”

### 동일 과제

“회사 면접에 입을 옷을 준비하려고 합니다. 상의·하의·구두 후보를 각각 비교해 하나씩 골라 주세요. 세 품목의 합계는 50만 원 이하로 맞추고, 선택 이유와 망설이는 점을 말해주세요.”

과제 문구는 참가자 모두에게 그대로 읽습니다. 진행자는 화면 사용법이나 추천 결과를 설명하지 않습니다. 참가자가 멈추거나 도움을 요청하면 요청 내용과 시점을 기록하고, 정해 둔 중립 안내만 제공합니다: “화면에서 이해되는 방식대로 계속 진행해 주세요.”

### 관찰 순서

1. 과제 제시 시각과 첫 행동을 기록합니다.
2. 참가자가 입력·조건 확인·추천 탐색·비교·결정하는 동안 말한 생각과 행동을 시간 순서로 메모합니다.
3. 성공/실패, 뒤로 이동, 잘못된 선택, 도움 요청, 막힘을 기록합니다.
4. 완료 또는 포기 시각과 선택 확신도를 묻습니다.
5. 사후 질문을 같은 순서로 묻습니다.
6. 세션 종료 후 개인 식별 정보가 기록되지 않았는지 확인합니다.

### 사후 질문

- 어떤 정보를 보고 후보를 선택했나요?
- 추천 이유와 주의점이 선택에 어떤 영향을 줬나요?
- 이해하기 어렵거나 신뢰하기 어려웠던 부분은 무엇인가요?
- 마지막 선택에 얼마나 확신하나요? (1 전혀 확신 없음 ~ 5 매우 확신)
- 실제 쇼핑에서 다시 사용한다면 어떤 점이 필요할까요?

## 4. 지표 정의

| 지표 | 기록 방법 |
|---|---|
| 과제 성공 | 상의·하의·구두 각각 하나씩 선택하고, 합계 50만 원 이하에서 이유를 설명하면 성공 |
| 완료 시간 | 과제 제시부터 선택 또는 포기까지의 분·초 |
| 오류 | 잘못 이해해 되돌아간 행동 또는 조건 위반 후보 선택 |
| 도움 요청 | 횟수와 발생 단계 |
| 선택 확신도 | 완료 후 1~5 자기 평가 |
| 근거 이해도 | 추천 이유·주의점 중 실제로 선택에 반영한 근거를 참가자가 설명한 내용 |
| 후보 확인 수 | 비교하거나 상세 확인한 서로 다른 후보 수와 품목별 수 |

성공률은 성공 인원 ÷ 전체 유효 세션 수로 계산합니다. 중단 세션은 중단 사유를 익명으로 기록하고 유효 세션 수와 별도로 보고합니다.

## 6. 문제 우선순위 기록

| 문제 | 발생한 세션 수 | 심각도 (0~3) | 사용자 영향 | 수정 비용 (S/M/L) | 우선순위 | 조치 / 재검증 |
|---|---:|---:|---|---|---|---|

- 심각도 0: 불편 없음
- 심각도 1: 가벼운 혼란, 과제 성공 영향 없음
- 심각도 2: 과제 지연 또는 일부 도움 필요
- 심각도 3: 과제 완료 불가, 잘못된 구매 판단 또는 핵심 정보 오해

P0는 심각도 3 문제와 반복되는 심각도 2 문제를 의미합니다. P0를 수정하면 테스트 참가자 2명 이상에게 같은 과제를 다시 요청하고 수정 효과와 부작용을 기록합니다.

## 8. UI 명세 확정 조건

실제 테스트 결과를 반영한 뒤 별도 UI 명세와 검색·추천 규칙을 확정합니다. 다음 항목을 각 화면마다 연결해야 합니다.

- 사용자 목표와 진입·다음 행동
- 필요한 필드와 데이터 출처
- 입력 검증·빈 결과·로딩·오류·재시도 상태
- 낮은 신뢰도 또는 근거 부족 상태
- 모바일 접근성·키보드 이동과 명확한 문구
- 연결된 요구사항 또는 테스트 관찰 근거

참가자 테스트 전에 UI 명세를 확정했다고 표시하지 않습니다.

## 9. 현재 막힌 점과 다음 행동

**막힌 점:** 세션은 아직 0/5입니다. 현재 초대된 4명으로 파일럿을 시작할 수 있고, Issue #7의 5명 목표를 채우려면 1명 추가 초대가 필요합니다. 참가 동의와 세션 일정 확정은 사람이 진행해야 합니다.  
**다음 행동:** 저장소 관리자가 초대된 참가자에게 링크를 전달하고 동의를 받은 뒤 동일한 ‘면접복 3품목·총 50만 원 이하’ 과제를 실행합니다. 익명 기록이 준비되면 결과 분석, P0 보완, 필요 시 2명 재검증, UI 명세 및 [상품 카탈로그·추천 점수 설계](../design/recommendation-catalog-and-ranking.md) 보완을 이어갑니다.
