# 설문 최종 분석 — 2026-10-12

> 상태: 응답 수집 종료 · 전체 21건 모두 핵심 유효 응답 · Google Forms 원본은 비공개 보관

## 결론

FITWISE는 광범위한 패션 플랫폼이 아니라 **온라인 의류 구매의 최종 판단을 돕는 도구**로 첫 프로토타입을 검증한다. 응답자는 상품 발견 이후에도 사이즈·핏을 판단하고 여러 후보를 비교하기 위해 쇼핑몰, 후기, 실측과 보유 의류 정보를 직접 오갔다. 따라서 첫 검증 범위는 `상황·예산 검색 → 3개 후보 비교 → 사이즈·핏 근거 확인`으로 고정한다.

설문만으로 제품 효과나 사업성을 확정하지는 않는다. 표본 21명은 목표 30명보다 적은 편의표본이며, 기능을 사용했을 때 결정 시간이 실제로 줄거나 지불 의향이 생기는지는 후속 과업 테스트로 검증한다.

## 분석 원칙과 표본

- 수집 기간: 2026-10-08 ~ 2026-10-12 KST
- 전체 응답: 21건
- 핵심 유효 응답: 21건
- 유효 기준: 최근 6개월 내 온라인 의류 구매 경험이 `예`인 응답
- 원본 응답은 접근이 제한된 Google Forms에만 보관한다.
- GitHub와 Project OS에는 이름, 이메일, 응답 원문과 개인을 추정할 수 있는 조합을 저장하지 않는다.
- 동일 응답자의 문항 간 조합을 공개하지 않고 문항별 집계만 기록한다.

## 구매 상황 코딩

단답형 구매 상황은 원문을 공개하지 않고 다음 비식별 코드로만 정리했다.

- 데이트·외출·여행처럼 **특정 상황에 입을 옷**
- 러닝·클라이밍처럼 **활동 목적이 분명한 옷**
- 출근처럼 **복장 맥락과 격식 수준이 필요한 옷**
- 계절 변화와 기온에 대응하는 **시즌 보충 구매**
- 부족한 기본 의류를 채우거나 다양한 조합을 만들기 위한 **옷장 보완 구매**
- 특별한 목적보다 디자인 선호가 앞선 **취향 중심 구매**

자연어 검색은 상품명만 받지 않고 `상황`, `활동`, `격식`, `계절`, `예산`, `보유 의류`를 확인 가능한 조건으로 구조화해야 한다.

## MVP 우선순위

### P0 — 다음 프로토타입에 포함

1. **상황·예산 자연어 입력과 조건 확인**
2. **서로 다른 전략의 후보 3개 비교**
3. **사이즈·핏 근거와 데이터 부족 상태**
4. **추천 이유·주의점·출처 구분**
5. **로딩·빈 결과·오류·재시도 상태**

### P1 — P0 검증 후 추가

1. 대표 보유 의류 3~5개를 태그로 입력하는 My Wardrobe
2. 후보별 보유 의류 조합 가능성과 중복 위험
3. 가격·할인·출처 갱신 시각 표시
4. 저장·제외·사이즈 적합 여부 피드백

### 보류 또는 제외

- 충분한 데이터와 동의·익명화가 없는 유사 체형 후기 개인화
- 얼굴·전신 사진 기반 체형 추정
- 사용권이 확인되지 않은 브랜드 상품·리뷰 수집
- 결제, 주문, 반품과 ERP 전체 기능
- AI가 가격, 재고, 실측 또는 후기를 생성하는 기능

## 검증 가능한 제품 결정

**진행 결정:** 합성 상품을 사용하는 `상황·예산 검색 → 3개 추천 결과 → 사이즈·핏 근거 → 비교` 프로토타입을 계속 개발한다.

**아직 결정하지 않는 것:** 실제 상품 연동, 추천 정확도 주장, 구독 가격, 제휴 수익, 자동 체형 분석과 전체 ERP 범위.

**중단 또는 수정 조건:** 5인 비교 과업에서 기존 방식보다 결정 시간이 줄지 않거나, 사용자가 추천 근거를 설명하지 못하거나, 데이터 부족 상태를 확정 추천으로 오해하면 현재 흐름을 수정한다.

## 한계

- 목표 유효 응답 30건에 도달하지 못한 21명의 편의표본이다.
- 인구통계와 구매 채널을 수집하지 않아 세그먼트별 차이를 설명할 수 없다.
- 문항별 집계만으로 같은 응답자의 행동과 요구 간 인과관계를 판단할 수 없다.
- 자기보고식 응답이므로 실제 결정 시간과 행동 로그가 아니다.
- 설문은 사용 의향, 반복 사용과 지불 의향을 검증하지 않았다.

따라서 이번 결과는 개발 우선순위를 정하는 근거이며 시장 규모나 제품 효과의 증명으로 사용하지 않는다.
