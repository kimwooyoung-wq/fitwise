### B. 경쟁 서비스 모바일 과업

공통 과업은 [경쟁 서비스 검증 계획](competitive-analysis.md)의 문장을 그대로 사용한다. 우선 앱 확인이 필요한 `W CONCEPT → Zigzag → ABLY` 순서로 실행한다. 결제·주문 버튼은 누르지 않는다.

서비스마다 아래 양식만 채운다.

```text
서비스 / 기기 / 로그인 여부:
완료 여부:
총 소요 시간:
검색어·필터 변경 횟수:
연 상품 상세 수:
외부 앱·검색 이동 횟수:
사이즈·핏 근거: 없음 / 제한적 / 충분함
세 후보 비교: 없음 / 제한적 / 충분함
검은 슬랙스 조합 지원: 없음 / 제한적 / 충분함
선택 확신도: 1 / 2 / 3 / 4 / 5
막힌 단계 한 줄:
```

화면 캡처를 남길 때는 계정명, 프로필 사진, 주문·배송 정보와 정확한 신체 치수를 가린다.

### C. 실기기 스모크 테스트

- [ ] 개발 빌드가 Android 또는 iOS에서 실행됨
- [ ] 상황·예산 입력 후 후보 3개가 표시됨
- [ ] 로딩 상태가 멈추지 않고 완료됨
- [ ] 조건에 맞는 상품이 없을 때 빈 결과 안내가 표시됨
- [ ] 네트워크 오류 후 재시도가 가능함
- [ ] 키보드가 버튼·결과를 가리지 않음
- [ ] 합성 데이터 안내가 보임
- [ ] 앱 종료·개인정보 노출·다른 사용자 데이터 노출이 없음

실패 항목은 기기·OS, 입력 조건, 기대 결과, 실제 결과, 재현 횟수만 기록한다. 상세 로그에 토큰이나 개인 데이터가 있으면 공개 저장소에 올리지 않는다.

### D. 5인 테스트

경쟁 서비스 비교와 실기기 스모크 테스트가 끝난 뒤에만 시작한다. 참가자 모집과 동의는 사람이 담당하고 결과는 `P01`~`P05`로만 기록한다. 세부 절차는 [5인 사용성 테스트 계획](usability-test-plan.md)을 따른다.

- 가설 백로그와 MVP 수용 기준 갱신
- 코드·문서 수정, 자동 테스트, 비밀값 검사와 기존 PR 갱신
- GitHub 원본과 Notion 상태의 불일치 점검

## 4. 중단하고 사람에게 알릴 조건

- 로그인 외에 결제·주문·구독 또는 권한 변경이 요구됨
- 실제 개인정보·신체정보·주문 이력을 공개 문서에 넣어야 진행 가능함
- 상품·이미지·후기의 사용 권리를 확인할 수 없음
- 다른 사용자의 데이터가 보이거나 삭제·복구가 불확실함
- PR 범위를 넘어 제품 목표나 P0 흐름이 달라지는 선택이 필요함

이 경우 우회 구현하지 않고 보류 사유와 필요한 결정을 Issue·PR에 기록한다.
