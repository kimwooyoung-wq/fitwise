## 목표

이미 존재하는 Expo·React Native 모바일 앱과 FastAPI API를 중복 생성하지 않고, PostgreSQL/pgvector 개발 환경과 문서·CI를 새 개발자가 재현할 수 있도록 정리한다.

## 범위 기준 (2026-11-25 정합화)

- 제품 헌장의 Android/iOS 모바일 우선 범위를 따른다. 웹 UI는 모바일 P0 흐름을 검증한 뒤 별도 승인으로 계획한다.
- 기존 `apps/mobile/`, `services/api/`, `/health`, 모바일/API/DB CI를 재사용한다. 새 `web/` 앱은 복제하지 않는다.
- 주차 7의 참가자 5인 테스트는 사용자 요청으로 대기 중이다. 참가자 검증과 주차 7 게이트는 미완료로 유지하며, 인프라 준비를 근거로 통과 처리하지 않는다.
- 운영 DB·실사용자 정보·실제 브랜드 상품은 사용하지 않는다. 로컬 DB에는 합성 fixture만 사용한다.

## 이미 확인된 기반

- Expo SDK 57 · React Native 앱과 `npm run lint`, `npm run typecheck`, `npm test` 스크립트
- FastAPI API와 `GET /health`
- PR CI의 mobile, API, PostgreSQL database 세 작업
- 앱별 `apps/mobile/.env.example`

## 필수 과제

- [ ] 루트 Docker Compose에서 로컬 PostgreSQL 16 + pgvector를 제공하고 포트는 로컬호스트에만 공개
- [ ] 루트 `.env.example`에 로컬 전용 DB 설정을 제공하고 비밀값 파일은 커밋되지 않도록 유지
- [ ] Windows PowerShell 기준 DB 초기화, migration, 합성 seed, API, 모바일 실행 절차와 문제 해결을 문서화
- [ ] CI 경로 필터에 Compose, 환경 예시, 개발 문서와 8주차 과제 문서를 포함
- [ ] 기존 `/health` 및 세 CI job의 범위를 문서에서 확인 가능하게 정리
- [ ] 신규 환경 15분 실행 기준은 사람의 클린 실행 전까지 미검증으로 표시

## 선택 과제

| 항목 | 통과 조건 | 확인 방법 |
|---|---|---|
| 재현성 | 새 환경에서 문서대로 로컬 DB·API·앱 구동 | 사람의 클린 실행 기록 (미완료) |
