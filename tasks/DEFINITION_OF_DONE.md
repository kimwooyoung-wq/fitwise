# FITWISE 주차 과제 완료 기준

이 기준은 모든 주차 과제에 공통으로 적용한다. 주차 문서의 개별 완료 조건과 이 문서 중 더 엄격한 조건을 사용한다.

## 상태 정의

| 상태 | 의미 |
|---|---|
| 계획 | 목표·산출물·완료 조건만 정의됨 |
| 진행 중 | Issue가 열렸거나 실제 작업이 시작됨 |
| 제출 | 산출물·검사·증빙을 포함한 PR이 열림 |
| 보완 요청 | 완료 조건, 검사, 증빙 또는 범위 정합성이 부족함 |
| 재제출 | 같은 PR에 보완 커밋과 재검증 결과가 반영됨 |
| 통과 | 완료 조건·검사·증빙·리뷰가 충족되고 `main` 반영이 승인됨 |

열린 PR, 자동 검사 성공 또는 코드 작성 완료만으로 `통과`가 아니다.

## 주차 시작 조건

- [ ] [프로젝트 헌장](../docs/product/project-charter.md)의 목표·비목표와 충돌하지 않는다.
- [ ] 관련 요구사항 ID 또는 검증할 가설 ID가 있다.
- [ ] 관련 Issue와 기존 PR·브랜치를 확인했다.
- [ ] 사용자 가치, 구현 범위, 제외 범위와 제공 데이터가 적혀 있다.
- [ ] 이번 주에 사람이 직접 확인할 항목과 외부 의존성이 적혀 있다.

## 주차 제출 조건

- [ ] 약속한 산출물이 저장소 또는 실행 가능한 환경에 존재한다.
- [ ] 각 완료 조건에 대응하는 검사 또는 관찰 증빙이 있다.
- [ ] 실행한 명령, 결과, 테스트 수, 경고와 미실행 이유를 기록했다.
- [ ] 정상·로딩·빈 결과·오류·재시도 중 변경 범위에 해당하는 상태를 확인했다.
- [ ] 개인정보·비밀값·상품 데이터 권리를 확인했다.
- [ ] 변경된 요구사항·API·데이터·운영 절차 문서를 갱신했다.
- [ ] 관련 Issue와 기존 PR에 결과를 연결했다.

## 다음 주 진입 조건

- 주차 문서의 진입 게이트가 증빙으로 충족되어야 한다.
- 미충족 조건은 사라지지 않으며 `보완 요청` 또는 다음 주의 명시적 선행 작업으로 이동한다.
- 일정이 늦어지면 P1·P2 범위를 줄인다. 보안, 데이터 무결성, 개인정보, 필수 테스트를 생략하지 않는다.
- 기술 프로토타입 통과와 사용자 가치 검증 통과를 서로 대신하지 않는다.

## 범위 이탈 검사

다음 질문 중 하나라도 답할 수 없으면 구현을 멈추고 Issue에서 범위를 다시 확인한다.

1. 이 작업이 해결하는 사용자 문제는 무엇인가?
2. 어떤 요구사항 또는 가설을 검증하는가?
3. 사용자의 어떤 행동 또는 어떤 테스트가 성공을 증명하는가?
4. 이 작업 때문에 미뤄지는 기존 P0 범위는 없는가?
5. 개인정보·상품 권리·추천 안전에 어떤 영향을 주는가?
