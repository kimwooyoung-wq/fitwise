# [13주] 의도 파서와 조건 확인

| 항목 | 내용 |
|---|---|
| 기간 | 2026-12-31 ~ 2027-01-06 |
| 단계 | Decision Engine |
| 이슈 | 미등록 |

## 목표

자연어 구매 목적을 검증 가능한 구조화 조건으로 바꾸고 사용자가 추천 전에 수정할 수 있게 한다.

## 필수 과제

- [ ] occasion·budget·styles·avoid·required_categories 스키마 확정
- [ ] 규칙 기반 의도 파서·검증·정규화 구현을 기준선으로 준비
- [ ] 규칙 기반 입력만으로 사용성 완료 기준을 만족하는지 확인
- [ ] 필요성이 확인된 경우에만 LLM 파서를 선택적으로 실험하고 규칙 기반 결과와 비교
- [ ] 파싱 실패·모호함·지원하지 않는 조건 처리
- [ ] 구조화 결과 확인·수정 UI 구현
- [ ] 대표·경계·악의적 입력 평가셋 50개 이상 작성
- [ ] 프롬프트 인젝션을 실행 명령이나 신뢰 데이터로 취급하지 않도록 방어

## 선택 과제

- [ ] 선택한 파서가 규칙 기반이면 이유를 기록하고, LLM을 실험하면 정확도·수정률·지연시간·비용·개인정보 노출을 비교

## 산출물

- 의도 파서 API와 조건 확인 화면
- `docs/architecture/intent-parser.md`
- 50개 이상 평가셋과 결과

## 완료 기준

| 항목 | 통과 조건 | 확인 방법 |
|---|---|---|
| 구조 정확도 | 평가셋 기준으로 규칙 기반 파서의 핵심 필드 일치율을 기록한다. LLM을 도입할 경우 동일 평가셋에서 85% 이상이며 규칙 기반보다 사용자 수정률·비용·지연시간을 고려해 개선됨 | 평가 스크립트 |
| 수정 가능성 | 사용자가 모든 추출 조건을 수정·삭제 가능 | E2E 테스트 |
| 안전 | 자유 텍스트가 시스템 명령·DB 쿼리로 실행되지 않음 | 보안 테스트 |
| 실패 처리 | 모호한 입력을 추측해 확정하지 않고 확인 요청 | 케이스 테스트 |

## 다음 주 진입 조건

선택한 파서의 기준선 결과와 선택 근거를 기록하고, 구조화 조건 API 계약이 동결되어야 한다. LLM 도입은 규칙 기반 대비 검증된 사용자 가치가 있을 때만 허용한다.
